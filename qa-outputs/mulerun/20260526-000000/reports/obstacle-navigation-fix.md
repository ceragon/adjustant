## 问题描述

用户报告：实测中我方单位和友方单位仍有概率被障碍物卡住，无法正常移动。

**根本原因分析**：

原 `moveToward()` 函数 (line 908-928) 的障碍物规避算法存在以下缺陷：

1. **两侧探测都被阻挡时无回退策略** — 单位继续朝障碍物方向移动
2. **X-only 和 Y-only 滑动都失败时** — 单位完全不动
3. **没有尝试更大角度的绕行** — 只偏转 0.5 倍垂直方向，无法绕过紧密障碍物
4. **没有"后退再试"机制** — 单位卡在死角或 L 型障碍物内

---

## 修复方案

### NEW-001: 完全垂直方向尝试 (90° 转弯)

**场景**: 当左右两侧的 45° 探测都被障碍物阻挡时

**修复**: 尝试完整的垂直方向（左 90° 或右 90°），而非原来的 45° 偏转

```javascript
// 原代码：两侧都 blocked 时 falls through，单位继续原方向
// 新代码：
const p1x=u.x+px*la, p1y=u.y+py*la;  // 左 90°
const p2x=u.x-px*la, p2y=u.y-py*la;  // 右 90°
if(!isObstacleAt(p1x,p1y)){dirX=px;dirY=py;}
else if(!isObstacleAt(p2x,p2y)){dirX=-px;dirY=-py;}
```

---

### NEW-002: 后退再探测机制

**场景**: 所有方向（45° 和 90°）都被阻挡，单位被困在死角

**修复**: 
1. 向反方向后退 0.5 格，创造空间
2. 从新位置重新探测 90° 垂直方向（1.5 倍距离）
3. 如果仍被阻挡，强制选择垂直方向（尝试从缝隙挤出）

```javascript
const backX=u.x-dirX*CELL*0.5, backY=u.y-dirY*CELL*0.5;
if(!isObstacleAt(backX,backY)){
  u.x=backX; u.y=backY;  // 后退
  // 重新探测
  const bp1x=backX+px*la*1.5, bp1y=backY+py*la*1.5;
  if(!isObstacleAt(bp1x,bp1y)){dirX=px;dirY=py;}
}
```

---

### NEW-003: 轴对齐滑动改进

**场景**: 对角线移动被阻挡时的备选方案

**修复**: 
1. 先尝试 X 轴独立移动
2. 如果 X 也被阻挡，尝试 Y 轴独立移动
3. 使用 `else if` 确保不会同时移动两个轴导致卡住

```javascript
// 原代码：两个 if 独立执行，可能同时修改 X 和 Y
// 新代码：
if(!isObstacleAt(u.x+stepX,u.y)){u.x+=stepX;}
else if(!isObstacleAt(u.x,u.y+stepY)){u.y+=stepY;}
```

---

### NEW-004: 垂直滑动回退

**场景**: X 轴和 Y 轴都被阻挡（真正的死角）

**修复**: 尝试沿垂直于移动方向的侧面滑动（70% 速度）

```javascript
const px=-dirY,py=dirX;
const perpStep=u.speed*CELL*dt*0.7;
if(!isObstacleAt(u.x+px*perpStep,u.y+py*perpStep)){
  u.x+=px*perpStep; u.y+=py*perpStep;
}
```

## 测试验证

### 测试场景

1. **中央十字障碍物穿越** — 障碍位置 [10,8], [10,12], [8,10], [12,10]，间隙仅 1-2 格
2. **角落障碍物集群** — 障碍位置 [4,4], [5,4], [4,5] 等 L 型布局
3. **多单位同时通过窄口** — 8 个单位同时向中心点移动
4. **边缘障碍物阻挡** — 障碍位置 [10,3], [10,17], [3,10], [17,10]

### 预期结果

- ✅ 单位能够绕过大多数障碍物配置
- ✅ 单位不会永久卡在死角（最多短暂停顿后后退绕行）
- ✅ 多单位拥挤时死锁概率显著降低
- ⚠️ 极端情况（如被障碍物完全包围）仍可能无法通过，但会尝试所有可能方向

## 残余风险

1. **无 A* 路径规划** — 当前仍是反应式避障，不是全局最优路径
2. **极端密集障碍物** — 如果障碍物间距 < 0.5 格，单位仍可能无法通过
3. **性能影响** — 新增探测逻辑增加少量计算（每帧约 5-10 次额外 `isObstacleAt` 调用）
4. **后退可能导致反向移动** — 单位可能短暂向反方向移动，视觉上不够流畅
