# MuleRun 原型迭代：战争迷雾系统

## 概述

为 MuleRun 单文件原型添加**双方独立计算的战争迷雾系统**，实现 RTS 风格的视野控制。本系统是原型 Phase 4 核心内容，独立于此前的 Phase 1-3 迭代。

**设计目标：**
- 玩家不再是上帝视角，必须通过单位前出侦察才能获取战场信息
- 保留"玩家是指挥官不是操作员"的核心理念——每次开火、每次推进都是有意为之的决策
- 为未来完整 RTS 版本（随机出生点、动态战场）奠定视野架构基础

**适用范围：** 仅 MuleRun `index.html` Canvas 2D 单文件原型，不影响 Spring Boot 主项目。

---

## 一、迷雾层级

战场视野分为**三层**，按渲染优先级从低到高：

| 层级 | 名称 | 视觉表现 | 内容可见性 |
|------|------|----------|-----------|
| L0 | 当前可见区 | 正常渲染（地形、单位、建筑、血条） | 全部实时更新 |
| L1 | 已探索阴影区 | 半透明深蓝灰色覆盖层，隐约可见底层网格 | 建筑保留黑影轮廓，单位完全隐藏 |
| L2 | 未探索区 | 程序化云雾纹理（静态缓存） | 全部内容遮挡 |

**渲染层级顺序（从底到顶）：**
1. 地形网格 → 可见单位 → 可见建筑
2. 已探索阴影区中的建筑黑影（去色 + 透明剪影）
3. 迷雾覆盖层（L2 云雾 + L1 半透明遮罩）

## 二、视觉样式规范

### 2.1 未探索区（云雾纹理）
- 使用**静态程序化噪声纹理**（Perlin/Simplex 噪声的简化实现），一次性生成后缓存到离屏 Canvas
- 纹理效果应呈现自然云雾状，而非均匀纯色
- 覆盖整个未探索区域，不显示底层任何内容

### 2.2 已探索阴影区
- 颜色：`rgba(20, 20, 30, 0.7)` 深蓝灰色半透明覆盖
- 能隐约看到底层网格线，营造经典战争迷雾质感
- 此区域中**建筑保留黑影**，**单位完全隐藏**

### 2.3 建筑黑影（在已探索阴影中可见）
- 图标：原建筑 emoji **去色 + 40% 透明度**，或显示灰色建筑剪影
- 血条：**完全不显示**（不更新状态，符合 RTS 规则）
- 选中光晕：**保留**（提示玩家它可交互）
- 状态：不随实际血量/破坏状态更新（始终保持第一次看到时的状态）

### 2.4 当前可见区
- 所有单位、建筑、血条、选中光晕、攻击动画正常渲染
- 无额外遮罩

## 三、视野计算规则

### 3.1 视野形状
- **菱形（曼哈顿距离）**：`|dx| + |dy| ≤ range`
- 不使用圆形或方形

### 3.2 视野范围
| 视野源类型 | 视野范围计算 |
|-----------|-------------|
| 移动单位（步兵/射手/骑兵） | `attackRange + 1`（从游戏配置的 `visionRange` 字段读取） |
| 建筑（HQ + 防御塔） | 固定值，略大于移动单位（建议 3-4 格） |

### 3.3 视野合并
- **所有视野源的视野范围取并集**
- 只要敌方单位/建筑落在任意一个我方视野源的菱形范围内，即标记为"当前可见"
- 建筑也提供视野（类似 RTS 的瞭望塔效果）

### 3.4 更新频率
- **每 Tick 计算一次（10Hz）**，与服务端 Tick 频率对齐
- 菱形范围计算轻量，10Hz 不会产生性能问题

### 3.5 对称性
- **双方独立计算**（玩家侧和敌方侧各自维护视野）
- MuleRun 原型中 AI 侧简化实现：AI 通过游戏状态获取完整信息（上帝视角），但**架构上保留对称接口**，未来可切换为 AI 也受迷雾限制

## 四、初始视野

### 4.1 开局视野覆盖
- **己方半场 + 己方建筑**初始可见
- 以地图中线为分界，玩家出生点所在半区完全暴露
- 己方 HQ 和防御塔始终在视野内（己方建筑不受迷雾影响）

### 4.2 敌方建筑初始状态
- 敌方建筑开局**不可见**（不在初始视野内）
- 当玩家单位前出侦察到敌方建筑位置时，该建筑进入"当前可见"
- 之后即使敌方建筑脱离视野，也会在已探索阴影区保留**黑影轮廓**

---

## 五、动态可见性

### 5.1 单位可见性
- **敌方单位在玩家视野内** → 实时显示（移动、血量、状态全部更新）
- **敌方单位离开玩家视野** → **立即从地图上消失**，变为迷雾/阴影覆盖
- 不保留"最后已知位置"标记（单位不像建筑那样保留黑影）

### 5.2 建筑可见性
- **敌方建筑在玩家视野内** → 实时显示（血量、状态更新）
- **敌方建筑离开玩家视野** → 在已探索阴影区保留**黑影轮廓**，不更新血量/状态
- 建筑一旦被探索过，永远保留黑影（直到被摧毁）

### 5.3 建筑摧毁后的迷雾状态
- 被摧毁的建筑在已探索阴影区**移除黑影**（或显示为废墟剪影）
- 未探索区域的建筑仍被云雾遮挡

## 六、交互限制

### 6.1 迷雾中的单位
- **不可点击、不可被选中**（玩家不知道它在哪）
- 无法对其下达任何指令

### 6.2 已探索阴影中的建筑黑影
- **可以被点击和选中**（建筑位置已知）
- 玩家可以对它下达攻击指令

### 6.3 视野丢失时的行为
- **敌方单位跑出视野后，我方单位的自动攻击立即停止**（丢失目标）
- 玩家手动下达的**移动指令继续执行**（单位继续向目的地移动）
- 不会自动切换攻击视野内的其他敌方单位（除非玩家重新下达攻击指令）

### 6.4 未探索区域交互
- 点击未探索区域（云雾覆盖）→ **自动寻路到该位置**
- 移动过程中**遭遇敌人不会自动攻击**
- **必须手动点击敌方单位才能发起攻击**
- 延续之前确认的"全军推进"逻辑：点击空地 = 移动指令，不包含攻击意图

---

## 七、RTS 移动-攻击行为

### 7.1 移动优先原则
- 单位接到移动/推进指令后，**优先完成寻路到达目的地**
- 移动过程中，即使路过敌方单位攻击范围，也**不会自动停下来攻击**

### 7.2 到达后自动索敌
- 单位到达目的地后，**自动搜索攻击范围内的敌方单位**
- 如果范围内有敌方单位 → 自动发起攻击
- 如果范围内无敌方单位 → 保持待机状态

### 7.3 攻击中断与恢复
- 攻击过程中目标离开视野 → **立即停止攻击**（丢失目标）
- 目标重新进入视野 → **不会自动恢复攻击**（需要玩家重新下达攻击指令）
- 这确保"每次开火都是有意为之的决策"

## 八、实现指引（供 MuleRun 参考）

### 8.1 云雾纹理生成
- 使用程序化噪声算法（简化版 Perlin/Simplex 噪声）
- 一次性生成纹理并缓存到离屏 Canvas `offscreenCanvas`
- 后续渲染直接 `ctx.drawImage(offscreenCanvas, ...)` 复用，避免每帧重复计算

### 8.2 视野计算伪逻辑
```
每个 Tick:
  1. 遍历所有我方视野源（单位 + 建筑）
  2. 对每个视野源，标记其菱形范围内的格子为"当前可见"
  3. 之前已探索但本次不在任何视野范围内的格子 → 降级为"已探索阴影"
  4. 从未被探索过的格子 → 保持"未探索"
  5. 根据每个格子的状态决定渲染层级
```

### 8.3 性能注意事项
- 菱形视野范围计算为纯整数运算，10Hz 频率下完全无压力
- 云雾纹理只生成一次，后续复用
- 建筑黑影状态在首次探索时缓存，后续不需要重新查询实际状态

## 九、验收标准

| 编号 | 验收项 | 预期效果 |
|------|--------|----------|
| FOW-01 | 开局视野 | 只看到己方半场 + 己方建筑，敌方半场被云雾覆盖 |
| FOW-02 | 单位前出侦察 | 敌方单位进入菱形视野范围时可见，离开后立即消失 |
| FOW-03 | 建筑黑影 | 敌方建筑首次暴露后，脱离视野仍保留去色剪影，血量不更新 |
| FOW-04 | 迷雾中单位交互 | 无法点击/选中迷雾中的敌方单位 |
| FOW-05 | 黑影建筑交互 | 可以点击/选中已探索阴影中的建筑黑影 |
| FOW-06 | 视野丢失攻击中断 | 目标离开视野后自动攻击停止，移动指令继续执行 |
| FOW-07 | 未探索区域点击 | 点击云雾区域 = 移动指令，遭遇敌人不自动攻击 |
| FOW-08 | 移动-攻击优先级 | 单位优先到达目的地，到达后才自动索敌攻击 |
| FOW-09 | 云雾纹理 | 未探索区域呈现自然云雾状，非均匀纯色 |
| FOW-10 | 建筑提供视野 | 防御塔/HQ 也贡献视野，推掉塔后前线视野丧失 |
| FOW-11 | 视野更新频率 | 视野变化平滑，无闪烁，10Hz 更新流畅 |
